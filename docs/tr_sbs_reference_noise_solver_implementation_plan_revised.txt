============================================================
1. 結論と原案からの主要変更
============================================================

現在の実装は geometric VE 固定ではない。VESDE、EDMSDE、PISCosineSDE、
zero-drift reference bridge、conditional score、Integrator 基底が既にある。
必要なのは、これらを捨てて新設することではなく、既存 API の互換移行と
sampling / density / training loss が同じ離散 kernel を使う仕組みの整備である。

実装順序を次へ変更する:
  Stage 0: 旧動作・制御量・密度比の仕様を固定し、互換テストを作る。
  Stage 1: kernel API と schedule API を接続し、zero-drift solver を拡張する。
  Stage 2: scalar OU の解析 reference と、前向き・後向き kernel を検証する。
  Stage 3: TR の FC target を監査・一般化し、OU の学習を解禁する。
  Stage 4: deterministic predictor の midpoint と刻み感度を評価する。

重要な修正:
  ・現行 ExponentialIntegrator は「exact noise + Euler drift」である。
  ・DiffusionTimeEuler は grid 変更に加え、drift の平均係数も変える。
  ・現行 network output は score 単位。FC target に -g(t) a_t を直結しない。
  ・OU の q は逆時間の定義次第で p と分散が異なる。共通分散を仮定しない。
  ・FC log_variance、GeneralASBS の consistency loss、atomic 側にも移行点がある。
  ・OU reference の正常動作と、OU TR-SBS の正しい学習を別の完了条件にする。

3. 実装前に固定する数式・意味
============================================================

3.1 制御量と loss の単位

現行の前向き SDE:
  dX = [f + g^2 u_theta] dt + g dW
  network_control = u_theta
  girsanov_control = g u_theta
  controlled_drift = g^2 u_theta

現行 ASBSTerminalCost の c_T は grad E + h_theta(T,X_T)。
初回は grad E のみ。gradient clipping の設定も既存仕様に含める。
現行の default FC CE は:
  a_T_legacy = gamma (c_T + u_i(T,X_T)) - u_i(T,X_T)
  loss = IW * ||u_theta(t,X_t) + a_T_legacy||^2
  評価時刻は 0、1、random t の3点。

AM の -g(t) a_t は Girsanov control の target。
現行 network output の target は -a_t となる。
元論文の control 定義と adjoint 式は ASBS Appendix A.1, Eq.26–38 を参照:
  https://arxiv.org/html/2506.22565v2#A1
ここでの network 単位への換算は、論文式と現行 ControlledSDE からの導出。

g^2 を MSE の重みに掛ける変更も、現行の unit weighting と区別する。
単位換算と同時に loss weighting を変えると比較に別要因が入る。

per_time_anchor_target=true は各時刻の u_i(t,X_t) を用いる。
false の旧 default は gamma=0 でも全時刻を u_i(T,X_T) に回帰させる。
この違いは互換テストに残す。旧 default の再現を gamma=0 の恒等更新と
同一視せず、新しい TR target の正しさも別のゲートで検証する。

3.2 Pref の意味と path ratio

run_with_logweights の self は実際に経路を生成する proposal R。
Pref というキー名でも、zero-control の base reference を意味しない。
通常の buffer 生成では self=prev_integrator、比較相手も同じオブジェクト。

  P_R = mu(x0) product_k p_R(x[k+1] | x[k])
  P_u = mu(x0) product_k p_u(x[k+1] | x[k])
  P_h = nu(xT) product_k q_h(x[k] | x[k+1])

  log_Ph_Pref = log nu(xT) - log mu(x0)
                 + sum log q_h - sum log p_R
  log_Pu_Pref = sum log p_u - sum log p_R

このキー・符号・dual 入力の -log_Ph_Pref は保存する。
nu が未正規化なら第一の比も定数分だけ未正規化となるため、mean をそのまま
絶対 KL と解釈しない。raw、gamma tempering、buffer rescale r、IW clipping を区別する。

3.3 正方向・逆方向

旧 backward step の dt は正の経過時間で、X_prev = X_current + bwd_drift * dt。
zero drift では bwd_drift = g^2 h_theta である。

最初の OU controlled solver は現行 h の absolute score 表現を保持する:
  elapsed reverse drift = -f(t,x) + g(t)^2 h_theta(t,x)
これは ASBS の backward half bridge の式からの拡張（Eq.17）:
  https://arxiv.org/html/2506.22565v2#S4

真の reference reverse kernel p_ref(X_s | X_t) は reference の marginal にも依存する。
forward transition を単に逆引きした密度でも、上記 h=0 の proposal でもない。
reference-residual 表現を後で加えるなら、score_ref の加減算、BC target、terminal cost、
reverse base drift を一緒に変更し、absolute score 表現と混在させない。

  4. 同一 fixed noise を新旧 kernel に渡せるようにし、数値再現を検証する。
  5. reference / solver / grid / time embedding / snapshot の識別子を定義する。

  ・atomic override、mean-free density、GeneralASBS の別 loss は共通化から漏らさない。

完了条件:
  legacy 設定の sample、loss、raw ratio、固定 log-weight 入力の dual 出力が一致。
  旧 checkpoint の読み込みが可能で、新規 metadata の default が legacy と明示される。

============================================================
5. Stage 1: 共通 kernel と zero-drift schedule / solver
============================================================

5.1 既存構造を拡張する API

NoiseSchedule（nn.Module、T=1 を初期仕様とする）:
  diffusion(t)
  cumulative_variance(t)                 = V(t)
  integrated_variance(t0,t1)             = V(t1)-V(t0)
  inverse_cumulative_variance(tau)

ZeroDriftReference:
  drift(t,x)=0
  reference_transition_parameters(x,s,t)
  reference_transition_log_prob(x_t,x_s,s,t)
  bridge_mean_cov / bridge_sample
  transition_score(x_t,x_0,t)
  adjoint_transport(t,T)=I
  bc_loss_weight(t,mode)

既存 diffsquare_integral、sample_posterior、cond_score_t0、total_variance は
互換 alias として残す。loss weighting は reference の物理法則とは別の設定。

BaseIntegrator に追加する pure API:
  transition_parameters(x,t0,t1,direction,controller_override=None)
  transition_log_prob(x_next,x,t0,t1,direction,controller_override=None)
  conditional_kl(other,x,t0,t1,direction)   （対応 kernel のみ）

step / step_backward は同じ parameters から sample する。
log_prob / mean の計算では乱数を生成しない。
sampling の no_grad と、loss 用 kernel 評価を分離し、controller の gradient を保持する。

run_with_logweights は p_R、p_u、q_h をそれぞれの integrator から取得する。
分散と log determinant を一つの base_sde から3 kernel に流用しない。
現行 log_Pref_Pu_det の mean-distance 式は、対応する Gaussian conditional KL にする。

5.2 旧 solver と新 solver を分ける

LegacyExactNoiseEuler（ExponentialIntegrator の public path を保持）:
  forward mean = x + g(t0)^2 u_theta(x,t0) Delta t
  reverse mean = x + g_bwd(interval)^2 h_theta(x,t1) Delta t
  both variances = Delta V

continuous VE / EDM の reverse coefficient は従来どおり右端を使う。
PIS cosine は現行 backward_step_diffusion の区間係数を使う。

DiffusionTimeEuler:
  forward mean = x + u_theta(x,t0) Delta V
  reverse mean = x + h_theta(x,t1) Delta V
  both variances = Delta V

この更新は network_control を interval 内で freeze する離散モデル。
uniform_t / uniform_tau は solver とは独立の grid 設定にする。
uniform_tau は tau_k = k V(1)/N、t_k=V^{-1}(tau_k)。

任意 grid の区間が PIS cosine の knot を跨ぐ場合も Delta V を全区間で積分する。
legacy の point diffusion drift と Delta V drift が同じとは仮定しない。

5.3 Schedule の実装順

既存 Geometric VE -> EDM -> DiscretePISCosine を先に adapter 化する。
その後 Constant、Linear を追加し、必要になった時点で ContinuousCosine を追加する。
DiscretePISCosine は既存 cosine_diffusion_schedule を再利用する。
reverse coefficient order、0.5 factor、piecewise V(t)、state_dict を保持する。
既存 CosineNoiseSchedule alias を別の continuous cosine の意味に置き換えない。

VE の現行式（r=sigma_max/sigma_min、r>1）:
  g(t)=sigma_min r^(1-t) sqrt(2 log r)
  V(t)=sigma_max^2 [1-r^(-2t)]
  V(1)=sigma_max^2-sigma_min^2
geometric という名称から増加方向の schedule を実装しない。

PIS cosine の noise knot 数と solver step 数を別パラメータとして扱う。
旧互換設定では双方128。刻み感度では noise 関数の knot を固定して solver のみ変更する。
V の逆関数は analytic、piecewise inverse、または決定的 monotone inversion を使う。
検証範囲では g>0、finite、V 単調、端点が有限。積分・逆関数は double で計算する。

5.4 Time conditioning / bridge / weighting

embedding_time: raw_t | normalized_diffusion_time | both（default raw_t）
score_hint_progress: raw_t | normalized_diffusion_time（default raw_t）
time_sampling: uniform_t | uniform_tau（default uniform_t）

TRIW の raw step=N(1-t) と hint=t target.score は別々に変更可能にする。
both は input 構造・parameter 数・checkpoint 互換性を変えるため別 ablation にする。
solver の grid を変えたことだけで FC/BC の random time sampling を変えない。
uniform_tau で旧 dt の loss integral を保つ場合、dt/dtau=1/g(t)^2、または
dt/dtau_norm=V(1)/g(t)^2 に対応する重みと端点除外区間の変換を明示する。

bridge は既存の mean=(1-V(t)/V(1))x0+[V(t)/V(1)]xT、
variance=V(t)[1-V(t)/V(1)] を再利用する。
旧 eps jitter を維持する互換経路と、端点を厳密に返す新 API を区別する。
BC の legacy weight は 1/[1+g(t)^2(1-t)/t]、terminal 項の weight は1。
none / variance normalization の追加は独立設定とし、default を変えない。

完了条件:
  VE / EDM / discrete cosine の旧互換が通る。
  新 schedule と uniform_tau が config で選べる。
  forward/reverse sampling と同じ kernel が IW、FC log_variance、評価で使われる。
  新 solver に未対応の loss / state representation は初期化時に明確に拒否する。

6. Stage 2: scalar linear Gaussian / OU machinery
============================================================

最初の対応範囲は flat、非 mean-free、scalar isotropic、constant / linear beta。
diagonal/full matrix、harmonic、一般 nonlinear drift は後続とする。

reference:
  dX=A(t)X dt+G(t)dW
  Phi(t,s): state transition
  Q(s,t)=integral_s^t Phi(t,r) G(r)G(r)^T Phi(t,r)^T dr

reference bridge を Gaussian conditioning で計算する:
  m_t=Phi(t,0)x0、m_T=Phi(T,0)x0
  C=Q(0,t)Phi(T,t)^T
  bridge mean = m_t + C solve(Q(0,T),xT-m_T)
  bridge covariance = Q(0,t)-C solve(Q(0,T),C^T)
  transition score = -solve(Q(0,t),x_t-Phi(t,0)x0)

最初の VP reference:
  A(t)=-beta(t)/2、G(t)=sqrt(beta(t))、source=N(0,I)
  J(s,t)=integral_s^t beta(r)dr
  phi=exp[-J(s,t)/2]、Q_forward=1-phi^2

LinearExponentialEuler の前向き controlled kernel:
  B(t)=G(t)G(t)^T（現行 network 単位に対応）
  mean_p = Phi(t,s)x_s + K_p(s,t)u_theta(x_s,s)
  K_p = integral_s^t Phi(t,r)B(r)dr
  covariance_p = Q(s,t)
VP では K_p=2(1-phi)、Q_p=1-phi^2。
exact なのは linear 部分・noise と frozen-control 区間の解。
state/time に依存する learned control を含む SDE 全体の exact solution ではない。

後向き controlled kernel は elapsed reverse base=-A、control=h_theta を freeze する。
unit VP、absolute score 表現では:
  mean_q = phi^(-1)x_t + 2[phi^(-1)-1]h_theta(x_t,t)
  Q_q = phi^(-2)-1
この式は上記 reverse drift を interval 内で積分した導出である。
Q_q と Q_p は一般に異なる。各 log_prob の Gaussian 定数も別々に計算する。
真の stationary reference reverse kernel は mean=phi x_t、covariance=Q_p であり、
この learned proposal q と区別する。h=0 を stationary reverse と呼ばない。

stationary preservation は uncontrolled reference の forward と、解析的な真の reverse
kernel で検証する。absolute h=-x を freeze した proposal は刻み依存なので、
その有限刻みの stationary preservation を解析 reference の条件と混同しない。

zero-drift limit は A -> 0、G を固定して検証する。
  Phi -> I、Q -> integral G G^T、K -> integral B
これが Stage 1 DiffusionTimeEuler の両方向を回復する。
VP の beta -> 0 は drift と diffusion を同時に消すため、この検証の代用にはならない。
OU の small-rate/short-interval 式には expm1 等を用い cancellation を避ける。

prior 比較:
  現行 gmm_mode の source.scale は30。N(0,I)へ変更した結果を reference-only 改善としない。
  machinery 検証は unit prior で行い、比較は双方の prior を一致させる。
  元の scale=s を保持する比較には G=s sqrt(beta)、stationary prior=N(0,s^2 I) を使える。
  この場合 Q_p=s^2(1-phi^2)、K_p=2s^2(1-phi) 等も同時に変更する。
  OU では integral G^2 だけでなく Phi、Q、terminal reference covariance を記録する。

完了条件:
  reference transition / bridge / score が解析値と一致する。
  controlled p と q の正規化、sample moments、density の整合性が通る。
  zero-drift limit が通り、path ratio が p/q の別 covariance でも正しく計算される。
  この段階の OU は machinery_validated。FC 理論確認前の通常学習は guard する。

============================================================
7. Stage 3: TR FC target の監査・OU 学習
============================================================

7.1 gamma=1 の基準

terminal adjoint = grad E + h_theta(T,X_T)
linear reference の transport = Phi(T,t)^T
  a_t = Phi(T,t)^T a_T
  network target = -a_t
  Girsanov control target = -g(t)a_t
VP なら kappa(t)=exp[-0.5 integral_t^T beta(r)dr]。
この基準は ASBS Appendix A.1, Eq.26–38 と network 単位の換算で確認する:
  https://arxiv.org/html/2506.22565v2#A1

7.2 0<gamma<1 の TR target は追加導出を完了条件にする

原案の「current terminal quantity を transport する」だけでは一般 TR matching の
正しさを保証できない。既存 u_i による path measure の混合項と、endpoint/per-time
anchor の差を扱う必要がある。

理論ノートに次を明示する:
  ・初期分布制約を含む TR objective と conditional normalization。
  ・P_h^gamma P_ui^(1-gamma) の path ratio と、その matching target の関係。
  ・reference Jacobian だけで十分か、frozen policy / running-cost 項が必要か。
  ・score 単位、符号、端点、loss weight、stopgrad の位置。
  ・continuous matching と有限刻み p/q による objective の近似範囲。

fc_target_mode を legacy_endpoint と general_reference_tr に分ける。
legacy_endpoint は旧 zero-drift の全動作を保存する。
general_reference_tr の導出後は gamma=0 の自身の policy 再現、gamma=1 の上式、
0<gamma<1 の小さな Gaussian 問題の oracle 比較を行う。
general_reference_tr と legacy_endpoint に差があればアルゴリズム変更として記録し、
Brownian と OU の reference 比較には同じ FC semantics を用いる。
旧 target に kappa を掛けただけの候補を「full general-drift TR-SBS」と認定しない。

7.3 Loss と学習経路の移行

FC log_variance:
  sum_k [log p_new(x[k+1]|x[k])-log p_ui(x[k+1]|x[k])]
    - gamma log_Ph_Pref_raw
を微分可能な kernel API で計算する。
現行 displacement / Euler drift の展開式は legacy kernel の高速経路にのみ残す。
OU の base drift、K、Q、midpoint をこの式から落とさない。

BC:
  absolute score 表現では OU の transition_score をそのまま target に使う。
  bc_loss_weight の候補は legacy / none / analytic variance normalization。
  isotropic reference の transition noise に対する score variance は 1/Q(0,t)。
  weighting はこの成分を基準にしても、endpoint conditioning や IW による
  target 全体の variance が同じとは仮定しない。t 下限と重みの上限を記録する。

corrector_gamma_mode:
  default none は保存する。既存 compute_corrector_gamma の raw score MSE proxy は
  schedule/time 積分を含む achieved path KL ではない。
  OU で non-none を対応させる前に kernel に基づく KL 計算か proxy の定義を監査する。
  未対応なら非 legacy reference との組合せを拒否する。

GeneralASBS:
  consistency の mean=x_next+h*dt は、現行の g^2 h 単位とも異なる。
  既存 loss の再現と、正しい q_kernel への統一を別モードで扱う。
  kernel API へ移行するか、新 reference/solver との組合せを初期化時に拒否する。
  「GeneralASBS」という class 名を general base drift 対応の証拠にしない。

Replay / checkpoint:
  raw と rescaled ratio を保持し、dense path の grid と behavior snapshot を識別する。
  reference / solver / grid / conditioning が変わる場合は旧 buffer を使用しない。
  clear_adjoint_buffer_per_outer_loop の旧 default=false は別の仕様として保存する。
  buffer を保持する比較では frozen policy の世代差の扱いを明記する。
  resume は kernel schema と設定を照合し、不一致を silent resume しない。

完了条件:
  旧 zero-drift legacy loss の回復と、general_reference_tr の正しさが別々に通る。
  OU の FC/BC の gradient、dual update、snapshot 更新、checkpoint resume が通る。
  bounded end-to-end smoke の後に remote の matched learning 比較へ進む。
  非linear f の JVP adjoint はこの Stage の必須範囲から外す。

============================================================
8. Stage 4: deterministic midpoint、後続拡張
============================================================

LinearExponentialMidpoint は deterministic half-step predictor で u_mid を決め、
full-step の mean を Phi x + K u_mid、noise covariance を Q とする。
predictor に stochastic noise を入れず、given x の Gaussian kernel を維持する。
reverse predictor も reverse base と q の係数を使い、forward のものを流用しない。
log_variance loss は predictor 内の network evaluation も含めて微分する。

Gaussian の log_prob が明示できることと、SDE の weak/strong 2次精度は別問題。
「2次精度」とは呼ばず、線形 controlled 問題と刻み感度から精度を検証する。
runtime は predictor 分の controller/score/energy evaluation を含めて比較する。
RK4、stochastic Heun、generic stochastic RK は今回の優先範囲外とする。

その後の任意拡張:
  diagonal/full covariance、preconditioned OU、harmonic OU、nonlinear adjoint。
mean-free / atomic では射影後の有効部分空間上の Gaussian density が必要。
full-dimensional logdet をそのまま流用せず、singular covariance の support、
effective dimension、prior、score の整合性を確認してから対応する。
対応までは既存 atomic legacy を維持し、新 OU 設定を明確に拒否する。

  source.scale、target、モデル・score hint、予算、clipping、epsilon を一致させる。
  unit VP 対 scaled OU、terminal reference covariance の差も明記する。
  「best zero drift」は新しい比較の結果から選ぶ。既存 tuning の結論を仮定しない。

D. OU solver
  exponential Euler / deterministic exponential midpoint の step 数感度。
  同じ reference 関数を固定し、network calls と energy/score calls を記録。
  rollout-only と retraining の結果を分ける。

  C/D の validation 後の任意段階。新 reference と epsilon sweep を同時に先行させない。

共通 metrics:
